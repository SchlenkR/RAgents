For developers

Use RAgents in your application

RAgents is a server with one JSON-RPC API. The web interface and VS Code use it, and your product can too.

  • Start the host beside your app, on a private port or over stdio
  • Call the same JSON-RPC 2.0 API as the UI
  • Follow runs live over Server-Sent Events
  • Tailor agents, tools and setups with your own profile and plugins
  • Typed contracts as OpenRPC and TypeScript declarations

Tailor a workspace for a task

  • A setup script creates agents, scripts and mini-apps
  • Start it again with one click
  • Ask for inputs before the run starts

The script builds the workspace, so the agents start with everything in place.

How it works

A setup is a tested TypeScript package that appears as a start card. Its script starts agents, TypeScript programs and mini-apps through the same functions the AI uses. A setup dialog can ask for values, such as a repository or a topic, before the run starts.

Learn more about setups

Everyone talks to everyone

  • Agents hand work to each other
  • Agents talk to scripts, scripts answer
  • People talk to agents and mini-apps
  • Mini-apps talk to people and agents
  • ... you get the idea :)

Agents write plain text to each other, addressed by handle, such as @agent1.

How it works

Each agent has its own model, prompt, history and handle. A coordinator takes the task and hands out work. A helper starts with no tools, a picked list, or all tools. When an agent asks you something, the choices appear in the chat and your answer goes back to that agent.

Learn more about agents

Agents with their own UI

  • The AI builds a UI while it works
  • Extensions ship UIs ready to use
  • You and the agent use the same UI and state
  • Your click goes straight to the agent
  • A new UI goes live after its tests pass

People are used to working with interfaces. A UI shows what the agent is doing, and you step in with a click.

How it works

A mini-app is a React view on the state of an agent or a TypeScript program. Its buttons call the program's typed functions directly. The AI type-checks and tests a new view before it goes live; if a rebuild fails, the old version stays active. In VS Code, a mini-app opens in its own editor tab.

Learn more about mini-apps

Tools are TypeScript functions

  • Register a typed function once, from your own plugin
  • Agents get it as a tool
  • AI-written code calls it, type-checked first
  • A button calls it directly, without a model
  • Programs call it when events arrive

Ten single tool calls mean ten model rounds. One TypeScript snippet keeps results, checks conditions and runs steps in parallel.

How it works

A snippet runs once and returns its result to the model. A program keeps its state and reacts to later messages. A setup starts agents, programs and UIs. All of them call the same typed functions, with the same permission checks.

Learn more about functions

Event-driven workflows

  • An agent starts when another one finishes
  • Replies arrive later as new input, nobody waits
  • A watcher without a model wakes an agent that hangs
  • Agents read the run's journal
  • Fork an agent with its memory

Every step of a run is an event in the journal. Agents and programs subscribe to the events they care about.

How it works

A subscription turns matching events, such as another agent's finished turn, into new input. A watcher is a TypeScript condition without a model, for example no progress for 120 seconds. Agents query the journal themselves and read other agents' transcripts for handoffs.

Distributed across server and laptop

  • Runs, agents and models live on the server
  • Laptops and browsers connect to a run
  • Messages flow both ways, live
  • Tools run on the machine that has the files
  • One server, many clients

Coordinate centrally, and let the tools run where the files are.

How it works

The host owns runs, journal, agents, plugins and model access. The workspace executor provides files, shell, Git, processes and language servers, next to the host or on a connected laptop. ragents connect fetches a client profile from the server, and the model relay shares models without revealing providers or keys.

01 On your laptop

Everything on one machine

  • Host, runs and tools in one process
  • VS Code starts it for you
  • Model calls go straight to your provider
  • No server to operate

Choose this when you try RAgents, or work alone on your own code.

$ npm install -g @schlenkr/ragents $ ragents start developer
Get started

02 On the server

Everything on the server

  • Runs, agents, models and files on one server
  • Open a link, nothing to install
  • Each run works in its own folder, isolated
  • Sign-in and rights per user

Choose this when your team or your clients should just open a link and start.

# in the browser https://ragents.example.com
Learn more about access

03 Server plus laptop

The server coordinates, your laptop does the work

  • Runs, agents and models stay on the server
  • Your laptop offers a folder to a run
  • Tool calls run on your files and return the result
  • Only you can see your files, even in a shared run

Choose this when the code lives on your machine, but coordination and models should be central.

# VS Code: open the folder, start a run. Or: $ ragents workspace-client \ https://ragents.example.com ~/project
Learn more about VS Code and the CLI

04 Connected laptop

Your runs, the team's setup and models

  • Runs and journal stay on your laptop
  • Profile, prompts, skills and plugins come from the server
  • Models by alias: provider and key never leave the server
  • Revoke access centrally, per user

Choose this when developers should work locally, but with the team's setup and models.

$ RAGENTS_TOKEN=<token> ragents connect \ https://ragents.example.com
Learn more about connecting

+ Move a run

Start here, continue there

  • Journal, model context and plugin storage move along
  • The run continues with the next message
  • A folder on your laptop stays bound to your laptop
  • Processes and language servers restart on first use

Choose this when a long run should leave your notebook for an always-on machine, or you want to inspect a server run locally.

$ pnpm run-transfer <source> <target> <runId>

Current status and limits

RAgents is under active development. Actor programs, their functions, state, and mini-apps belong to one run. Events and time-based triggers need an agent or TypeScript actor. Schedules, a user-management interface, and several people in the same run are not available yet. Profiles may require sign-in or run without it. General user permissions can limit new runs to approved setups and hide settings, models, and technical views while keeping chats and mini-apps usable.
