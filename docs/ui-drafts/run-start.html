Grundlage

Der Start eines Runs

"Neue Unterhaltung" ist ein neuer Run. Und ein Run beginnt nicht zwingend mit einem Chat, sondern mit einem Einstieg, den ein Plugin mitbringt: Promptkarte, Skill, Leitfaden oder Script.

Drei Entwürfe für die Startfläche, jeder mit Varianten als Mockup. Die Bausteine darin sind die heutigen: Startoptionen, Starter, Promptkarten, Leitfaden-Dialog, Composer. Neu ist nur ein vierter Einstieg, das Run-Script, und die Frage, wo der Composer steht.

Was heute da ist

Der leere Chat zeigt Startoptionen, zwei Kartenlisten und darunter den Composer. Der Run entsteht erst, wenn eine Nachricht gesendet wird.

a b c
  1. aDer Composer ist die Mitte des Bildschirms und der einzige Weg in den Run. Jeder Einstieg endet in ihm.
  2. bZwei Listen mit gleicher Optik und getrenntem Code: Starter (Skill, optional Leitfaden) und Promptkarten (Text).
  3. cEine Promptkarte fügt nur Text ein; senden muss der Benutzer. Ein Starter sendet sofort oder öffnet einen Leitfaden.
  4. dDer Entwurf heißt "Neue Unterhaltung", obwohl er ein Run wird: Journal, Actors, Fläche, Werkzeuge.

Wo es reibt

  • Falsches Wort. Ein Run ist mehr als eine Unterhaltung: Der Chat ist nur ein Ausschnitt.
  • Der Composer dominiert, obwohl er selten der erste Schritt ist. Bei den Referenzfällen und beim Feature-Lauf beginnt der Run mit einer Karte.
  • Ein Aufbau ist nie deterministisch. Alles, was einen vorgebauten Run ausmacht, entsteht durch Werkzeugaufrufe des Koordinators; eine Promptkarte ist Text, der ihn dazu anweist.
  • Ein Plugin, das den Run vorkonfigurieren will, hat keinen Ort dafür. Es kann Karten, Skills und Leitfäden liefern, aber kein Script, das beim Start läuft.

Was jeder Entwurf leisten muss

  • Vier Einstiegsarten mit einer Optik: Promptkarte, Skill, Skill mit Leitfaden, Run-Script.
  • Art nie nur über Farbe: ein Textabzeichen (Prompt, Skill, Script) und die Aktionsbeschriftung tragen den Unterschied.
  • Freitext bleibt erreichbar, mit höchstens einem Klick.
  • Startoptionen gelten für alle Einstiege und stehen deshalb über ihnen.
  • Zwanzig Einstiege müssen tragen (produkt hat heute zwanzig Karten plus zwei Starter).
  • Passt in beide Rahmen: die heutige Oberfläche und die Kommandobrücke aus dem Bedienkonzept.
Entwurf 1

Galerie der Einstiege

Die Startfläche ist ein Raster aus Einstiegen, nach Plugin gruppiert. Der Composer ist einer davon und rückt an den Rand.

neu Einstieg als ein Beitragneu Run-Scriptbleibt Startoptionen, Leitfaden, Skills

Dafür

  • Ein Vertrag für Einstiege statt zwei Registries; das Web zeigt eine Liste.
  • Der Composer bleibt einen Klick entfernt, dominiert aber nicht.
  • Das Run-Script bekommt seinen Platz, ohne dass die Fläche anders aussieht.

Dagegen

  • Wer nur chatten will, hat einen Schritt mehr (A und C), oder eine kleinere Bühne (B).
  • Die Gruppierung nach Plugin ist technisch, nicht fachlich; eine kuratierte Reihenfolge braucht `order` über Plugins hinweg.

Empfehlung

1 A für den Anfang, 1 C sobald ein zweites Plugin Einstiege liefert. Die Composer-Zeile hält den Freitext einen Klick entfernt, ohne die Bühne zu besetzen. Die Karte im Raster (1 B) ist hübsch, verliert aber ab zwölf Einstiegen die Übersicht; die Liste (1 C) trägt beliebig viele und braucht dafür Filter und Suche.

Alle drei Klickpfade aus Entwurf 2 sind Pflicht, weil sie die drei Arten erst unterscheidbar machen: Prompt öffnet, Skill sendet oder fragt, Script baut.

Im Rahmen der Kommandobrücke 3 A. Der Entwurf darf anders aussehen als der Run; die Spalte (3 B) ist zu schmal für Beschreibungen und lässt zwei Drittel des Bildschirms leer.

Was davon ohne Engine-Änderung geht

  • Wording "Neuer Run", Galerie, Composer-Zeile, Klickpfade A und B: reines Web, die Registries bleiben.
  • Ein Vertrag für Einstiege: Server-Registries zusammenlegen, kein Journalzustand betroffen.
  • Klickpfad C braucht die Start-Route ohne Nachricht, den host-seitigen Check-Test-Install eines Script-Pakets und `run_configure`, damit ein Script Titel und Primary-Actor setzen kann; Details in docs/concepts/run-start.md, Teil 2.
