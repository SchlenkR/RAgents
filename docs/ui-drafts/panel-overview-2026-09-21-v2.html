Panel der VS-Code-Erweiterung: Übersicht und Einstellungen, Fassung 2

Entwurf, 21.09.2026

Diese Fassung setzt die Entscheidung um. Sie zeigt nur noch einen Weg, keine Alternativen mehr - bis auf die eine offene Frage, wie ein Run und eine Vorlage ihre Umgebung nennen.

  • Entwurf B ist weg. Es bleibt die überarbeitete Fassung von Entwurf A.
  • Ziel heißt jetzt Umgebung. Überall: Überschriften, Zeilen, Dialoge, Fließtext.
  • Keine Chipreihe mehr. An ihrer Stelle steht oben der Abschnitt "Umgebungen" mit allen Umgebungen als flachen Zeilen: Name, Art, Zustand mit Punkt und, wenn etwas zu tun ist, ein kleiner Knopf "Anmelden", "Erneut versuchen" oder "Starten". Die Problemstreifen aus Fassung 1 entfallen, die Zeilen übernehmen das. Gefiltert wird nicht.
  • Kein Abzeichen an Runs und Kacheln. Drei Vorschläge stehen im zweiten Abschnitt nebeneinander bei 420 Pixeln zur Wahl - dazu der Alltagsfall mit genau einer Umgebung, in dem die Kennzeichnung ganz verschwindet.
  • Nichts Formularartiges mehr in der Liste. "Neue Umgebung", "Bearbeiten" und "Anmelden" öffnen einen Dialog im Panel; nur das Entfernen fragt in der Zeile zurück. Inline-Formulare machen die Liste unübersichtlich, ein Dialog hat einen Anfang und ein Ende.

Unverändert gilt: ein Klick auf eine Kachel startet den Run in ihrer Umgebung und öffnet die Arbeitsspalte, ohne Zwischenseite. Farben, Radien und die Schriftgröße 13 px kommen aus apps/web/src/ui/theme.css (dunkles Thema).

1Übersicht

Drei Abschnitte auf einer Fläche: Umgebungen, Runs, Startvorlagen. Gezeigt mit der Kennzeichnungsvariante b (Farbkante); die Wahl steht im nächsten Abschnitt.

Neu: Übersicht -> Kachel -> Run läuft Heute: Übersicht -> Neuer Run -> Neuer Run -> Vorlage -> Run

Für die Umsetzung

  • Ersetzt TargetCard in apps/web/src/panel/OverviewPage.tsx durch drei Abschnitte auf einer Fläche; RunRow bleibt fast unverändert, EntryRow wird zur Kachel.
  • Zustand und Farbton kommen unverändert aus apps/web/src/panel/target-state.ts (stateLabel, stateTone, runStateLabel, runTone).
  • Die Kacheloptik stammt aus docs/ui-drafts/start-entry-alternatives.html (.prompt-grid, .prompt-card) und aus den Tonflächen von apps/web/src/ui/ListDetail.tsx (data-tone, --tone, Skill rund, Run-Script eckig).
  • Die Suche ist die vorhandene Filterlogik aus apps/web/src/StartSurface.tsx (StartEntryLibrary), ohne ListDetail: der misst sich selbst und würde bei 420 Pixeln zur Liste mit Detailseite (Entscheidungen vom 19. und 21.09.2026).
  • Die Umbenennung von Ziel auf Umgebung betrifft die Oberflächentexte und sollte auch in den Vertrag: TargetView, TargetState, TargetRun, TargetEntry und TargetKind in apps/web/src/panel/contract.ts, dazu apps/vscode/src/overview-model.ts (resolveTarget, newRunChoices) und die Befehlstexte der Erweiterung.
  • TargetEntry trägt heute nur id, title, description und action; für die Kategoriegruppen muss category (besser auch tags) mit in den Vertrag und in den Aufbau des PanelState.
  • Ein Klick auf eine Kachel schickt { action: "newRun", name, entryId }, die Kachel "Neuer Run" dasselbe ohne entryId; danach öffnet die Erweiterung direkt die Arbeitsspalte. Die Startauswahl der Spalte (apps/web/src/StartSurface.tsx) hat im Panel-Fall dann keine Aufgabe mehr.
  • "Anmelden" in der Umgebungszeile öffnet denselben Dialog wie in den Einstellungen; apps/web/src/panel/LoginForm.tsx wandert dafür in den Dialogkörper und wird von beiden Seiten benutzt.

2Wie ein Run und eine Vorlage ihre Umgebung nennen

Zur Wahl, alle bei 420 Pixeln, damit der enge Fall entscheidet. Rechts daneben der Alltag: genau eine Umgebung, und die Kennzeichnung fällt ersatzlos weg.

Für die Umsetzung

  • Alle drei Varianten brauchen dieselbe Angabe am Eintrag: die Umgebung, aus der ein Run oder eine Vorlage stammt. Sie steht schon im PanelState, weil der Aufbau je Umgebung erfolgt (apps/vscode/src/overview-model.ts).
  • Variante b braucht zusätzlich eine stabile Farbe je Umgebung. Sie sollte aus dem Namen abgeleitet werden (feste Palette, Index über einen Hash des Namens), damit sie ohne Einstellung auskommt und sich beim Umsortieren nicht ändert.
  • Variante a kostet bei zwei Umgebungen doppelt so viele Gruppenüberschriften, weil Umgebung und Kategorie beide gruppieren; Variante c kostet Breite im Titel, was bei 420 Pixeln zuerst weh tut.
  • Die Ausblendung bei genau einer Umgebung ist eine Bedingung an einer Stelle: targets.length > 1 in OverviewPage.tsx. Der Abschnitt "Umgebungen" bleibt auch dann sichtbar, er zeigt nur eine Zeile.

3Einstellungen

Die Liste zeigt und entfernt, alles andere ist ein Dialog: Inline-Formulare machen die Liste unübersichtlich, ein Dialog hat einen Anfang und ein Ende.

Für die Umsetzung

  • Ersetzt TargetRow, AddServer, AddProfile und die aufklappbare Credentials-Komponente in apps/web/src/panel/SettingsPage.tsx: eine Zeilenliste, ein Knopf, zwei Dialoge.
  • Die Dialoge sind vorhandene Bausteine: apps/web/src/ui/dialog.tsx beziehungsweise apps/web/src/ui/modal.tsx mit apps/web/src/ui/modal-controller.ts; der Panel-Einstieg braucht denselben Modal-Halter wie die Web-App.
  • Der Vertrag kann das schon: addServer, addProfile, pickProfile, remove, login und logout in apps/web/src/panel/contract.ts; PanelState.pickedProfileFile trägt den im VS-Code-Dateidialog gewählten Pfad in den Dialog zurück.
  • Für "Bearbeiten" fehlt eine Aktion: heute gibt es nur Anlegen und Entfernen. Entweder eine neue Aktion updateServer/updateProfile, oder der Dialog schickt remove und danach addServer - das erste ist sauberer, weil sonst die gespeicherten Anmeldedaten verloren gehen.
  • Neu nötig ist die Vorschlagsliste der Profile im Host-Ordner: ein Feld am PanelState (etwa profileSuggestions), gefüllt in apps/vscode/src/settings.ts oder apps/vscode/src/overview-model.ts aus ragents.hostPath beziehungsweise ragents.lastHostPath. Der Name kommt aus dem Dateinamen (ragents.config.<profil>.ts) und bleibt änderbar.
  • Das Entfernen behält die zweistufige Bestätigung der heutigen Zeile; ein Fehler der letzten Aktion steht weiter als TargetView.problem in der Zeile, ein Fehler der Einstellung als PanelState.problem über der Liste.

Offline nutzbar, alles in dieser Datei: kein externes Skript, keine externe Schrift, keine Netzverbindung. Die Knöpfe sind Attrappen; nur der Breitenschalter oben ist aktiv.
